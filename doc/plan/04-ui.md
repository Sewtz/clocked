## WP4-T1 — `App.vue` view-switcher + lifecycle wiring

- **Goal:** Root component that:
  - calls `store.init()` on mount,
  - starts/stops the per-second tick,
  - listens for `visibilitychange` and calls `store.onVisible()`,
  - renders the right view based on `store.viewState`.
- **Files:** `src/App.vue`.
- **Approach:**
  ```vue
  <script setup lang="ts">
  import { onMounted, onBeforeUnmount, computed } from 'vue'
  import { useClockStore } from '@/stores/clock'
  import ClockInView from '@/components/ClockInView.vue'
  import RunningView from '@/components/RunningView.vue'
  import BreakOverlay from '@/components/BreakOverlay.vue'

  const store = useClockStore()

  function onVisibility() {
    if (document.visibilityState === 'visible') {
      store.onVisible()
    }
  }

  onMounted(() => {
    document.addEventListener('visibilitychange', onVisibility)
    store.init()
  })

  onBeforeUnmount(() => {
    document.removeEventListener('visibilitychange', onVisibility)
  })

  const view = computed(() => store.viewState)
  </script>

  <template>
    <main class="min-h-dvh flex flex-col items-center justify-center bg-neutral-50 text-neutral-900">
      <template v-if="store.loadStatus !== 'ready'">
        <div class="text-neutral-400">Loading…</div>
      </template>
      <template v-else>
        <ClockInView v-if="view.kind === 'clock-in' || view.kind === 'clocked-out'" />
        <RunningView v-else-if="view.kind === 'running'" />
        <BreakOverlay v-else-if="view.kind === 'break'" />
      </template>
    </main>
  </template>
  ```
  Note: `clocked-out` reuses `ClockInView` — the same view shows the big red button to "clock in (resume)".
- **Dependencies:** WP3-T7.
- **Acceptance criteria:**
  - The app renders "Loading…" briefly while storage loads, then the right view appears.
  - Switching the device to background and back triggers `store.onVisible()`.
  - The `min-h-dvh` Tailwind class makes the app fill the dynamic viewport (handles iOS safe-area).
- **V&V:** `pnpm dev` — manual check that the page loads without errors and shows `ClockInView` (since storage is empty).
- **Pitfalls:**
  - Do not import the components with dynamic imports — keep the bundle simple. Code-splitting can come later if needed.
  - If `min-h-dvh` doesn't work in your Tailwind v4 setup, fall back to `min-h-screen`. The dvh unit is preferred for mobile browsers' dynamic toolbars.

## WP4-T2 — `ClockInView` (big red button + adjustments + custom time)

- **Goal:** The initial screen. Big round red button to clock in at the current time. Below it: three buttons `+1min / +5min / +10min` and a `<input type="time">` for custom time.
- **Files:** `src/components/ClockInView.vue`, `src/components/ClockInView.test.ts`.
- **Approach:**
  ```vue
  <script setup lang="ts">
  import { ref } from 'vue'
  import { useClockStore } from '@/stores/clock'
  import { localEpochForTodayMs } from '@/domain/date'

  const store = useClockStore()
  const customTime = ref('')

  function clockInNow() {
    store.clockIn()
  }

  function adjust(minutes: 1 | 5 | 10) {
    // clock in at (now - minutes) — equivalent to saying "I started N min ago"
    store.clockIn(Date.now() - minutes * 60_000)
  }

  function onCustomTime() {
    if (!customTime.value) return
    const [h, m] = customTime.value.split(':').map(Number)
    const startMs = localEpochForTodayMs(h, m)
    store.clockIn(startMs)
    customTime.value = ''
  }
  </script>

  <template>
    <div class="flex flex-col items-center gap-8">
      <button
        type="button"
        class="w-48 h-48 rounded-full bg-red-600 text-white text-2xl font-semibold shadow-lg active:scale-95 transition-transform"
        @click="clockInNow"
      >
        Clock In
      </button>

      <div class="flex gap-3">
        <button type="button" class="px-4 py-2 rounded-lg bg-neutral-200 text-neutral-800" @click="adjust(1)">+1min</button>
        <button type="button" class="px-4 py-2 rounded-lg bg-neutral-200 text-neutral-800" @click="adjust(5)">+5min</button>
        <button type="button" class="px-4 py-2 rounded-lg bg-neutral-200 text-neutral-800" @click="adjust(10)">+10min</button>
      </div>

      <label class="flex flex-col items-center gap-2 text-sm text-neutral-600">
        Custom time
        <input
          v-model="customTime"
          type="time"
          class="px-3 py-2 rounded-lg border border-neutral-300"
          @change="onCustomTime"
        />
      </label>
    </div>
  </template>
  ```
  Note: the +Nmin buttons here are an alternate UX to the WP3-T4 `adjustStart` action — here we're at clock-in time with no entry yet, so we pass a shifted start to `clockIn()`. After the entry exists, the adjustment buttons (if shown in `RunningView`) call `store.adjustStart(N)`.

  Test cases:
  - Renders the big red button with text "Clock In".
  - Clicking the big button calls `store.clockIn()` with no args.
  - Clicking `+5min` calls `store.clockIn` with `Date.now() - 5 * 60_000` (mock `Date.now`).
  - Entering `09:30` in the time input and triggering `change` calls `store.clockIn` with the right epoch.
  - Empty custom time does not call `store.clockIn`.
- **Dependencies:** WP3-T2 (clockIn action), WP1-T2 (date helpers).
- **Acceptance criteria:**
  - All test cases pass.
  - The button has `min-h-[44px]` touch target (the 192px circle well exceeds this).
  - In `pnpm dev`, tapping the button (or clicking) starts the timer and switches the view.
- **V&V:** `pnpm test -- src/components/ClockInView.test.ts` then `pnpm dev` for a manual smoke check.
- **Pitfalls:**
  - `<input type="time">` returns `'HH:MM'` string. Split on `:`, parse to numbers, hand to `localEpochForTodayMs`.
  - The `change` event fires on blur or Enter; `input` fires on every keystroke. Use `change` to avoid mid-typing calls.
  - iOS Safari shows a native time picker for `<input type="time">`. This is the OS dialog we want.

## WP4-T3 — `RunningView` (elapsed display + edit + reset + clock-out)

- **Goal:** The main running screen. Shows `HH:MM` of worked time. Provides:
  - clock-out button,
  - reset button,
  - edit clock-in time (reuse `<input type="time">` pre-filled with the recorded start),
  - optional +1/+5/+10 buttons to adjust the open work segment's start (per WP3-T4).
- **Files:** `src/components/RunningView.vue`, `src/components/RunningView.test.ts`.
- **Approach:**
  ```vue
  <script setup lang="ts">
  import { computed, ref } from 'vue'
  import { useClockStore } from '@/stores/clock'
  import { formatHHMM } from '@/domain/format'
  import { localEpochForTodayMs } from '@/domain/date'

  const store = useClockStore()

  const display = computed(() => formatHHMM(store.displayMs))

  const editTime = ref('')
  function prefillEdit() {
    const first = store.entry?.segments[0]
    if (first && first.type === 'work') {
      const d = new Date(first.start)
      editTime.value = `${String(d.getHours()).padStart(2, '0')}:${String(d.getMinutes()).padStart(2, '0')}`
    }
  }
  function applyEdit() {
    if (!editTime.value) return
    const [h, m] = editTime.value.split(':').map(Number)
    store.editClockIn(localEpochForTodayMs(h, m))
  }

  function adjust(minutes: 1 | 5 | 10) {
    store.adjustStart(minutes)
  }
  </script>

  <template>
    <div class="flex flex-col items-center gap-6">
      <div class="text-6xl font-mono tabular-nums">{{ display }}</div>

      <div class="text-sm text-neutral-500">worked (excl. breaks)</div>

      <button
        type="button"
        class="px-6 py-3 rounded-lg bg-neutral-800 text-white"
        @click="store.clockOut()"
      >
        Clock Out
      </button>

      <div class="flex gap-3">
        <button type="button" class="px-4 py-2 rounded-lg bg-neutral-200" @click="adjust(1)">+1min</button>
        <button type="button" class="px-4 py-2 rounded-lg bg-neutral-200" @click="adjust(5)">+5min</button>
        <button type="button" class="px-4 py-2 rounded-lg bg-neutral-200" @click="adjust(10)">+10min</button>
      </div>

      <label class="flex flex-col items-center gap-2 text-sm text-neutral-600">
        Edit clock-in time
        <input
          v-model="editTime"
          type="time"
          class="px-3 py-2 rounded-lg border border-neutral-300"
          @focus="prefillEdit"
          @change="applyEdit"
        />
      </label>

      <button
        type="button"
        class="mt-4 text-sm text-red-600 underline"
        @click="store.reset()"
      >
        Reset day
      </button>
    </div>
  </template>
  ```
  Test cases:
  - Renders `formatHHMM(store.displayMs)` in the display div.
  - Clicking "Clock Out" calls `store.clockOut`.
  - Clicking "+5min" calls `store.adjustStart(5)`.
  - Entering a time and triggering `change` calls `store.editClockIn` with the right epoch.
  - Clicking "Reset day" calls `store.reset`.
- **Dependencies:** WP3-T2, WP3-T3, WP3-T4.
- **Acceptance criteria:**
  - All tests pass.
  - The displayed time updates every second (verified manually in `pnpm dev`).
  - All buttons are at least 44×44px touch targets.
- **V&V:** `pnpm test -- src/components/RunningView.test.ts` then `pnpm dev`.
- **Pitfalls:**
  - The `tabular-nums` Tailwind class keeps the HH:MM digits from shifting width every second.
  - `@focus` prefills the time input so the user sees the current clock-in time when they interact.
  - Reset is destructive and should probably have a confirm dialog — add a simple `confirm('Reset the day?')` guard (WP6 can polish).

## WP4-T4 — `BreakOverlay` (countdown + auto-resume)

- **Goal:** Full-screen overlay shown while `store.isOnBreak`. Displays "Break — NN:NN remaining". Closes automatically when the break ends (because `store.viewState` switches back to `running` via the recompute pipeline).
- **Files:** `src/components/BreakOverlay.vue`, `src/components/BreakOverlay.test.ts`.
- **Approach:**
  ```vue
  <script setup lang="ts">
  import { computed } from 'vue'
  import { useClockStore } from '@/stores/clock'
  import { formatMMSS } from '@/domain/format'

  const store = useClockStore()

  const remainingMs = computed(() => {
    const ends = store.breakEndsAt
    if (!ends) return 0
    return Math.max(0, ends - store.now)
  })

  const remaining = computed(() => formatMMSS(remainingMs.value))
  </script>

  <template>
    <div class="absolute inset-0 flex flex-col items-center justify-center bg-amber-100 text-amber-900">
      <div class="text-2xl font-semibold mb-4">Break</div>
      <div class="text-6xl font-mono tabular-nums">{{ remaining }}</div>
      <div class="mt-4 text-sm text-amber-700">Resumes automatically</div>
    </div>
  </template>
  ```
  Test cases:
  - Renders "Break" label.
  - When `store.breakEndsAt = now + 30 * 60_000`, the remaining display is `'30:00'`.
  - When `store.breakEndsAt = now + 60_000`, the remaining display is `'01:00'`.
  - When `store.breakEndsAt` is undefined, remaining is `'00:00'` (no crash).
- **Dependencies:** WP3-T3 (getters).
- **Acceptance criteria:**
  - All tests pass.
  - When the store's break ends (manually advance `now` in a test), the overlay's parent (`App.vue`) switches to `RunningView`.
- **V&V:** `pnpm test -- src/components/BreakOverlay.test.ts`.
- **Pitfalls:**
  - The overlay does **not** auto-close itself — `App.vue` is what hides it when `store.viewState` changes from `'break'` to `'running'`. This is the correct separation of concerns.
  - Clock-out and clock-in buttons are intentionally absent here — breaks can't be skipped.

## WP4-T5 — WP4 integration test

- **Goal:** A single end-to-end component test mounting `App.vue` with a real Pinia store, exercising the full view-switching flow.
- **Files:** `src/App.test.ts` (or `src/components/App.integration.test.ts`).
- **Approach:**
  ```ts
  import { describe, it, expect, beforeEach, vi } from 'vitest'
  import { mount } from '@vue/test-utils'
  import { createPinia, setActivePinia } from 'pinia'
  import App from './App.vue'

  beforeEach(() => {
    setActivePinia(createPinia())
    vi.useFakeTimers()
  })

  it('shows ClockInView on empty storage', async () => {
    const wrapper = mount(App)
    // let init resolve
    await vi.runOnlyPendingTimersAsync()
    expect(wrapper.text()).toContain('Clock In')
  })

  it('switches to RunningView after clock-in', async () => {
    const wrapper = mount(App)
    await vi.runOnlyPendingTimersAsync()
    await wrapper.find('button.rounded-full').trigger('click')
    expect(wrapper.text()).toContain('worked')
  })
  ```
  You can extend this test to cover clock-out → clocked-out view, edit, reset.
- **Dependencies:** WP4-T1 through WP4-T4.
- **Acceptance criteria:**
  - The integration test passes.
  - It does not depend on real `Date.now` — uses fake timers.
- **V&V:** `pnpm test`.
- **Pitfalls:**
  - The Pinia store persists to `fake-indexeddb` during these tests. Use `clearAllEntries()` in `beforeEach` (import from `@/storage/entries`) to keep tests isolated.
  - `vi.useFakeTimers()` + `vi.runOnlyPendingTimersAsync()` is the cleanest way to drive the async `init` and the per-second tick deterministically.

## WP4-T6 — Clocked-out account display + Reset day

- **Goal:** In `ClockInView`, when `store.viewState.kind === 'clocked-out'`, show `formatHHMM(store.workedMs)` with label "Worked today" above the red button, and a Reset day button below the custom-time picker. In the fresh clock-in state (no entry), neither element is rendered.
- **Files:** `src/components/ClockInView.vue`, `src/components/ClockInView.test.ts`.
- **Approach:**
  - Add `computed` import to the `<script>` block; import `formatHHMM` from `@/domain/format`.
  - Add computed `showAccount = store.isClockedOut` and `workedToday = formatHHMM(store.workedMs)`.
  - Between the `<h1>` heading and the red button, insert a `v-if="showAccount"` block:
    ```html
    <div v-if="showAccount" class="flex flex-col items-center gap-1">
      <div class="text-5xl font-mono tabular-nums text-neutral-900 dark:text-neutral-100">{{ workedToday }}</div>
      <div class="text-sm uppercase tracking-wide text-neutral-500">Worked today</div>
    </div>
    ```
  - After the custom-time `<label>`, insert a Reset day button (same styling as the one in `RunningView`):
    ```html
    <button
      v-if="showAccount"
      type="button"
      class="min-h-[44px] px-4 py-2 text-sm text-brand underline dark:text-brand-dark active:scale-95 transition-transform focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-brand"
      @click="store.reset()"
    >
      Reset day
    </button>
    ```
  - Tests (4 new cases in `ClockInView.test.ts`):
    1. Renders worked time and "Worked today" label when clocked out (clock in → advance → clock out → mount → assert text contains `01:00` and `Worked today`).
    2. Does NOT render "Worked today" in fresh clock-in state.
    3. Renders "Reset day" button when clocked out, and clicking it calls `store.reset`.
    4. Does NOT render "Reset day" button in fresh clock-in state.
- **Dependencies:** WP3-T2, WP3-T5 (`reset`), WP4-T2.
- **Acceptance criteria:** all 4 new tests pass; all existing tests still pass; `pnpm preview` manual check confirms the account appears after clock-out and disappears after Reset.
- **V&V:** `pnpm test -- src/components/ClockInView.test.ts` then `pnpm test` (full suite).
- **Pitfalls:** guard with `store.isClockedOut` — do not render on the fresh clock-in state; reuse `RunningView`'s reset button classes for visual consistency; do not add a per-second tick for the clocked-out display (value is static since no open work segment).
